A release process for prompts

A prompt is code that nobody compiles. At Dring I built the system that treats it like code anyway: every change starts from a failing test, passes an independent review, and is measured again before it ships. This is Agent Factory, a Claude Code workspace of specialist agents and skills that runs that process.

    Agent Factory

    243 commits

    The workspace above. Six specialist agents with fixed roles and twenty skills that act on the prompt service, the test service, the production database and ElevenLabs.

    • Specialists that cannot overstep: the tester never edits prompts, the engineer never writes tests, the validator can only read.
    • Clone testing on the real ElevenLabs runtime, so a voice change is proven on a copy of the live agent first.
    • Model-switch and cost-probe skills that migrated the agent fleet to a model 12.5× cheaper per token, measuring every agent on the way.
    • A static prompt linter and a transcript analyst that turns real calls into reproducible test cases.

    Prompt Test Service

    170 commits

    A dockerized FastAPI and PostgreSQL service that runs test suites against any prompt over HTTP and stores every run.

    • Simulated multi-turn conversations with mocked tools, scored criterion by criterion by an LLM judge.
    • Multi-run execution to separate a real regression from model variance.
    • Transport errors and missing mocks are reported as failures to run, never as passes.
    • A report UI and a run history that make before-and-after claims checkable.

    Prompt Service

    493 commits

    The production home of every agent's instructions: voice prompts, chat prompts and the end-of-call analyzers that score each conversation.

    • Turkish and English voice prompts tuned for how people actually speak on the phone: pacing, fillers, numbers read aloud.
